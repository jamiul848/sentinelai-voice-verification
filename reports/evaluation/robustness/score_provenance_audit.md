## 1. Executive Summary & Forensic Verdict

This forensic audit was initiated to resolve a critical research question:
> **"Were the reported Phase 5C and Phase 5D performance metrics ($\theta^* = 0.6057$, Dev EER = 3.41%, Test FAR = 1.94%, Test FRR = 2.65%, Test Accuracy = 97.45%, Test ROC-AUC = 0.9976) calculated from real ECAPA-TDNN neural network inference on LibriSpeech audio recordings, or from synthetic demonstration scores?"**

### The Definitive Finding:
1. **The similarity scores in `outputs/evaluation/dev/scores.csv` and `outputs/evaluation/test/scores.csv` are 100% synthetic.**
2. They were generated by `generate_synthetic_dataset()` in `scripts/run_evaluation.py` using NumPy Gaussian random number generators ($\mathcal{N}(0.76, 0.08^2)$ for genuine and $\mathcal{N}(0.44, 0.09^2)$ for impostor scores).
3. We proved this mathematically: the scores in `test/scores.csv` match `np.random.default_rng(1337).normal(...)` with an **exact absolute difference of 0.0 across all 2,624 trials**.
4. The trial IDs in `scores.csv` (`synth-test-clean-00000` through `02623`) and speaker IDs (`spk_0` through `spk_29`) are synthetic pseudo-identifiers that have **zero intersection** with the true UUIDs and physical speaker IDs in `outputs/evaluation/test/trials.csv`.
5. **No neural network inference was executed to produce `scores.csv`.** Zero embeddings were extracted or cached to disk for the trial manifests.
6. **No data fabrication was intended.** The synthetic score generator was written as a demonstration fallback in `scripts/run_evaluation.py` to allow testing the evaluation mathematics when embedding extraction was skipped via `--skip-embedding-extraction` in Phase 5B. However, these demonstration scores were subsequently treated as empirical benchmark results in the Phase 5C and Phase 5D reports.

## 3. Task 2: Forensic Inspection of `scripts/run_evaluation.py`

Inspection of [`scripts/run_evaluation.py`](file:///e:/sentinelai-voice-verification/scripts/run_evaluation.py) revealed the exact mechanism:

### Lines 207–218: The Fallback Trigger
```python
    # Fallback to synthetic if embeddings not yet computed
    logger.info("Raw audio embeddings not pre-extracted; generating representative trial scores...")
    n_gen = len([r for r in rows if r["ground_truth_label"] == 1])
    n_imp = len([r for r in rows if r["ground_truth_label"] == 0])
    ds = generate_synthetic_dataset(
        split_name=split_name,
        n_genuine=n_gen,
        n_impostor=n_imp,
        seed=42 if "dev" in split_name else 1337,
    )
    scorer.write_scores_csv(ds, scores_csv)
    return ds
```

### Lines 111–125: Construction of Pseudo-Speaker IDs & Synthetic Trial IDs
```python
    trials = []
    for i in range(len(all_scores)):
        is_gen = all_labels[i] == 1
        trials.append(
            ScoredTrial(
                trial_id=f"synth-{split_name}-{i:05d}",
                claimed_speaker_id=f"spk_{i % 30}",
                actual_speaker_id=f"spk_{i % 30}" if is_gen else f"spk_{(i + 1) % 30}",
                trial_type="genuine" if is_gen else "impostor",
                ground_truth_label=int(all_labels[i]),
                similarity_score=float(round(all_scores[i], 6)),
                split=split_name,
                model_identifier="speechbrain/spkrec-ecapa-voxceleb",
            )
        )
```

### Forensic Findings:
1. `trial_id` was hardcoded with prefix `f"synth-{split_name}-{i:05d}"`.
2. `claimed_speaker_id` was generated using modulo 30: `f"spk_{i % 30}"`.
3. `actual_speaker_id` was assigned either `f"spk_{i % 30}"` (genuine) or `f"spk_{(i + 1) % 30}"` (impostor).
4. `all_scores` was sampled directly from NumPy Gaussian random variables without computing 192-dimensional embeddings or vector dot products.
5. Once written to `outputs/evaluation/{dev,test}/scores.csv`, line 148 of `run_evaluation.py` cached these files:
   ```python
   if scores_csv.exists() and not use_synthetic:
       logger.info(f"Loading existing score manifest from {scores_csv}...")
       return scorer.load_scores_csv(scores_csv, split_name=split_name)
   ```
   Consequently, all subsequent evaluation scripts (including `run_robustness_analysis.py`) loaded these synthetic scores from disk under Option 1.
